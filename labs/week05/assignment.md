## Part 7 — Clause and goal order experiment

Do **not** “fix” these examples before observing them.

First compare:

~~~prolog
passed_bs0030_a(Student) :-
    student(Student),
    passed(Student, bs0030).

passed_bs0030_b(Student) :-
    passed(Student, bs0030),
    student(Student).
~~~

Query both with a variable. Do they describe the same intended conjunction for this finite knowledge base? In what order do they generate/constrain candidates?

Next inspect `bad_ancestor/2` in the starter. It places recursive work before useful progress. You do not need to run a query that hangs. Explain in comments why ordinary leftmost, depth-first Prolog search can recurse indefinitely before reaching the base clause.
